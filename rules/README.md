# 청주대학교 규정집 (모바일 웹앱)

청주대학교 규정관리시스템(https://rule.cju.ac.kr/lmxsrv/main/main.srv)의 규정을 휴대폰에서 검색하고,
규정 간 위임조항과 동일·유사 내용을 검증하는 웹앱입니다. GitHub Pages 주소의 `/rules/`에서 열고,
브라우저 메뉴의 **홈 화면에 추가**를 누르면 앱처럼 설치됩니다.

## 기능

| 탭 | 내용 |
| --- | --- |
| 검색 | **낱말 검색**: 규정명·본문 검색(전체/규정명/본문), 띄어쓰기 무시, 여러 낱말 AND, `"구절"` 검색, 분류 필터, 최근 검색어<br>**개정 기간**: 조문별 최종 개정일(조문 끝 "(변경 2019. 5. 7.)" 등 개정 표시의 가장 최근 날짜)로 기간 안에 개정·신설·삭제된 조문 찾기. 규정 하나 또는 전체 규정(규정별로 묶어 표시) |
| 규정목록 | 분류별 목록, 즐겨찾기 |
| 위임관계 | 규정별 상위(근거)·하위(위임) 규정, 위임 체계도, 준용·참조, 대상 미지정 위임("별도로 정한다"), 외부 법령 인용 |
| 검증 | **정합성 점검**: 없는 규정·조항 인용, 근거 조항에 위임 문언 없음, 하위 규정 미확인 등<br>**상위법 비교**: 규정명을 입력하면 관련 상위 법령(인용·근거·분야)을 찾고, 검증을 누르면 인용 상태·법의 숫자 기준·비슷한 법 조문과의 문장·숫자 차이를 대조<br>**동일·유사 조항**: 조·항 단위 중복 검출, 차이 부분 표시, 기간·학점·인원 등 숫자 불일치 표시 |
| 데이터 | 최신 데이터 받기, JSON·HWPX·DOCX·TXT 가져오기, 본문 붙여넣기, 내보내기 |

규정 보기 화면 맨 아래에는 **별표·서식** 목록이 있습니다. 누르면 규정관리시스템과 같은 방식(`/lmxsrv/fileDown.srv`에
`FILE_SEQ`·`FILE_TYPE`을 POST)으로 파일을 받습니다. 수집기가 첨부 링크(`fileDown('번호', 'attach')`)를 `rules.json`의
`attachments`에, 받기 함수 원문을 `fileDown`에 저장합니다. 번호를 모르는 파일은 원문 화면을 엽니다.

규정 보기 화면에서는 「규정명」·제N조 인용이 링크로 바뀌고(없는 대상은 빨간 물결선), 조마다 위임·근거 배지와
**유사 조항 찾기**가 있습니다.

## 규정 데이터 수집

규정관리시스템은 보안 정책(CORS) 때문에 다른 주소의 웹앱이 직접 읽을 수 없습니다. 그래서 수집기로
전문을 모아 `rules/data/rules.json`으로 올려 두면 앱이 그 파일을 읽습니다.

```bash
pip install -r rules/tools/requirements.txt
python rules/tools/cju_rules_crawler.py            # 목록 자동 탐색 → rules/data/rules.json
git add rules/data/rules.json && git commit -m "규정 데이터 갱신" && git push
```

자동 탐색이 안 되면:

- `--viewer "/lmxsrv/law/....srv?SEQ={seq}"`: 브라우저로 규정 하나를 열었을 때 주소 형식을 지정
- `--scan 1-3000`: 규정 번호(SEQ) 범위를 직접 지정
- `--from-dir 폴더`: 브라우저에서 "다른 이름으로 저장"한 규정 HTML/TXT 파일에서 추출
- `--insecure`: 인증서 오류가 날 때만 사용

학교 서버에 부담을 주지 않도록 요청 사이에 0.5초(`--delay`) 쉽니다. 학교 밖·해외 IP는 막혀 있을 수 있으니
교내망 PC에서 실행하는 것을 권장합니다.

## 한 번에 업데이트하기 (업데이트 프로그램)

규정 수집 → 법령 확인 → GitHub 업로드를 버튼 하나로 실행합니다. 등록된 학교 PC에서 실행하세요.

1. `rules/tools/`의 `update_gui.py`, `규정업데이트.bat`, `cju_rules_crawler.py`, `law_check.py`를 한 폴더에 둡니다.
2. `규정업데이트.bat`을 더블클릭하고, 처음 한 번 법령 API 인증키(OC)와 GitHub 토큰을 넣습니다.
   - GitHub 토큰: GitHub → Settings → Developer settings → Personal access tokens → Fine-grained tokens →
     Generate new token → Repository access에서 이 저장소만 선택 → Permissions의 Contents를 Read and write로
3. **업데이트 시작**을 누르면 끝까지 자동으로 진행되고, 바뀐 규정 목록을 보여줍니다.

- 바뀐 파일만 올리고, 수집된 규정 수가 기존보다 크게 적으면(80% 미만) 수집 실패로 보고 올리지 않습니다.
- 규정이 바뀌면 개정 이력(`changes.json`: 바뀐 규정의 이전·이후 본문, 최근 30회)을 함께 올립니다. 앱의 규정목록 맨 위
  **최근 개정**과 규정 보기의 **개정 비교**에서 조문별 신구대비표로 볼 수 있습니다.
- "실행 전 최신 프로그램 받기"를 켜 두면 저장소에 올라온 최신 수집·확인 프로그램으로 실행합니다. 업데이트 프로그램
  자신이 바뀌었으면 새 버전으로 바꾼 뒤 다시 실행해 달라고 안내합니다.
- 설정은 이 PC의 `%APPDATA%\cju-rules\config.json`에만 저장됩니다.

## 국가 법령 인용 확인

규정이 인용한 법률·시행령·시행규칙·고시·훈령·예규는 국가법령정보센터(law.go.kr) Open API로 확인합니다.
현행 법령인지, 인용한 조가 있는지, 삭제된 조인지를 점검하고 인용한 조문의 현행 내용을 저장합니다.

```bash
python rules/tools/law_check.py --oc 인증키          # rules/data/rules.json → rules/data/laws.json
python rules/tools/law_check.py --oc 인증키 --debug 고등교육법   # API 응답 확인
```

인증키(OC)는 [open.law.go.kr](https://open.law.go.kr)에서 OPEN API를 신청할 때 직접 정합니다. 신청할 때 프로그램을
실행할 PC의 공인 IP를 등록하고, 공동활용 법령종류는 '대한민국 현행법령'과 '현행 행정규칙'의 목록 JSON·본문 JSON을 고릅니다. `laws.json`을 `rules/data/`에 올리면 앱의 정합성 점검에 반영되고, 본문의 초록색 법령
인용을 누르면 현행 조문이 보입니다.

## 상위법 비교

규정명을 입력하면 관련 상위 법령을 보여줍니다.

- **인용·근거 법령**: 규정 본문에서 인용한 법령(제1조 목적 조항에서 든 법령은 근거 법령)
- **분야**: `topics.json`의 `areas`에 규정 제목 낱말로 정한 분야별 기본 법령(학칙·학사 → 고등교육법 등)

고른 법령과 **검증**하면 다음을 보여줍니다.

- 인용 상태(없는 법령·조, 삭제된 조, 규정 개정 뒤 바뀐 법 조문)
- 법 숫자 기준 대조(아래)
- 비슷한 법 조문: 규정 조문(항 단위)과 문장이 비슷한 법 조문을 찾아 차이를 표시하고, 숫자가 다르면 **숫자 다름**
- 인용한 법 조문과 나란히 보기

법령 전체 조문은 업데이트 프로그램이 `data/lawtext/`에 법령마다 파일로 올리고(`law_check.py --text-dir`),
앱은 검증할 때만 받습니다. 전체 조문이 아직 없으면 인용한 조문만 대조합니다.

### 법 숫자 기준 자동 대조

관련 법령 전체 조문에서 "30주 이상", "3개월 이내", "40시간을 초과할 수 없다"처럼 숫자와 한계어가 있는 문장을 뽑아
최소(이상)·최대(이내·이하·미만·초과할 수 없다·까지) 기준으로 삼고, 숫자 앞말(문맥)이 비슷한 규정 문장의 같은 단위
숫자와 비교합니다. **법 최소 기준 미달**, **법 최대 기준 초과**, **법과 다름**, **같음**으로 나눕니다.

- 앞말이 짧으면 조 제목도 비슷해야 하고, "제7호의 사유로 인한"처럼 호 번호가 있으면 같은 호끼리만 짝짓습니다.
- 값이 다른 후보가 비슷한 점수로 여럿이면 모호하므로 뺍니다.
- 규정 하나를 검증할 때 결과에 나오고, 화면 아래 **법 숫자 기준 자동 대조 (규정집 전체)**에서 모든 규정을 한 번에 대조합니다.

## 분석 기준

- **부칙**: 개정 때마다 붙은 부칙을 단위로 나눠 규정·법령 인용을 점검합니다. 개정 당시 기준의 경과 규정일 수 있어
  지적은 한 단계 낮춰(오류→주의) 표시합니다.
- **폐지 규정**: 머리말에 "폐지 날짜" 줄이 있는 규정은 폐지로 보고 점검·중복 비교에서 뺍니다. 현행 규정이 폐지된
  규정을 인용하면 오류로 알립니다.
- **상위법 개정 확인**: 인용한 법령 조문의 `<개정 …>`·`[본조신설 …]` 날짜가 규정의 마지막 개정일보다 뒤면 주의로 알립니다.

- **위임**: 「규정명」 뒤에 "으로/에서 정한다" → 이 조항이 대상 규정에 위임
- **근거**: 「규정명」 제N조 뒤에 "에 따라/에 의하여/의 위임" → 이 규정이 그 조항에 근거
- **준용**: "~을 준용한다"
- 괄호 없이 쓴 규정명도 등록된 규정명과 일치하면 인식합니다. 「고등교육법」 같은 외부 법령은 검증 대상에서 뺍니다.
- 동일·유사 조항: 공백·문장부호·항 번호를 없앤 뒤 4글자 조각의 겹침(자카드 유사도) 또는 한쪽이 다른 쪽에
  포함된 비율로 판정합니다.

자동 분석은 문언 패턴에 기반하므로, 결과는 검토 대상 목록으로 활용하고 최종 판단은 원문으로 확인해 주세요.

## 파일

- `index.html`: 앱 화면
- `engine.js`: 파싱·검색·위임 분석·유사도 엔진 (Node에서도 `require` 가능)
- `data/sample.json`: 체험용 예시 데이터 (실제 규정 아님)
- `data/rules.json`: 수집기 출력 (수집 후 추가)
- `tools/cju_rules_crawler.py`: 규정 수집기
- `tools/law_check.py`: 국가 법령 인용 확인(국가법령정보센터 Open API)
- `tools/update_gui.py`, `tools/규정업데이트.bat`: 수집·확인·업로드를 한 번에 하는 업데이트 프로그램
- `data/laws.json`: 법령 확인 결과 (확인 후 추가)
- `data/changes.json`: 개정 이력 (업데이트 프로그램이 규정 변경 시 추가)
- `data/topics.json`: 분야별 기본 법령 목록(상위법 비교의 '분야')
- `data/lawtext/`: 법령 전체 조문 (업데이트 프로그램이 올림)
