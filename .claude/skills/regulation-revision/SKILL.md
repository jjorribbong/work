# 청주대학교 규정 개정 업무 지침

규정 개정을 요청받을 때마다 아래 절차를 **같은 순서, 같은 방식**으로 적용한다.
단계를 건너뛰거나 임의로 양식을 바꾸지 않는다. 판단이 필요한 부분은 추측하지 말고 사용자에게 확인한다.

## 0. 최종 결과물 (반드시 3종)

| # | 결과물 | 양식 | 파일명 규칙 |
|---|--------|------|-------------|
| 1 | 규정 개정 요청서 | `regulation/templates/` 기본 양식 1쪽 | `{규정명}_개정요청서및신구대비표_{YYYYMMDD}.hwpx` (1·2를 한 파일로) |
| 2 | 신·구조문 대비표 | `regulation/templates/` 기본 양식 2쪽~ | (위와 같은 파일) |
| 3 | 개정안이 반영된 규정 파일 | 규정집에서 받은 원본 규정 파일 | `{규정명}_개정안_{YYYYMMDD}.{확장자}` |

- 결과물은 작업 폴더 `regulation/output/{YYYYMMDD}_{규정명}/` 에 저장하고, 검증 결과 요약(`검증보고.md`)을 함께 남긴다.
- 원본 파일(규정 원문, 검토의견 엑셀)은 `regulation/input/{YYYYMMDD}_{규정명}/` 에 그대로 보존하고 절대 덮어쓰지 않는다.
- 업로드된 양식의 서식(글꼴, 표 구조, 머리글, 결재란 등)은 그대로 유지하고 내용만 채운다. hwpx 양식은 `anthropic-skills:hwpx-autofill-conversion`, docx는 `anthropic-skills:docx`, xlsx는 `anthropic-skills:xlsx` 스킬을 사용한다.

## 1단계. 개정 대상 규정 파일 확보

1. 청주대학교 규정집 https://rule.cju.ac.kr/lmxsrv/main/main.srv 에서 개정 대상 규정을 검색하여 **최신 시행본** 파일을 다운로드한다.
2. 확인 사항: 규정명, 규정번호(분류번호), 제정일, 최종 개정일, 시행일, 소관 부서. 개정요청서와 신구대비표에 그대로 사용한다.
3. 다운로드한 파일은 `regulation/input/...` 에 원본 그대로 저장한다.
4. **접속이 안 되는 경우**(클라우드 세션 네트워크 차단 등): 임의의 내용으로 대체하지 말고, 사용자에게 규정 파일을 직접 업로드해 달라고 요청한다. 업로드 파일의 최종 개정일이 규정집 최신본과 같은지 사용자에게 확인받는다.

## 2단계. 개정 요청서 및 신구대비표 작성 방법

### 사용 양식 (등록 완료)
- **기본 양식**: `regulation/templates/개정요청서_신구대비표_양식_직원보수규정예시.hwpx`
  — 한 파일 안에 [1쪽] 요청서 + [2쪽~] 신·구조문 대비표(별표 대비 포함)가 들어 있다. 이 파일을 복사해 내용만 바꿔 쓴다.
- 보조 예시: `regulation/templates/개정요청서_신구대비표_양식_정관예시.hwpx` (조문 일부만 바뀌는 경우 `-----` 표기 예시)
- 결과물 1·2(요청서, 신구대비표)는 이 양식에 따라 **하나의 hwpx 파일**로 만들되, 파일명은 `{규정명}_개정요청서및신구대비표_{YYYYMMDD}.hwpx` 로 한다.
- 예시 파일 속 문구에는 작성기준에 맞지 않는 부분이 있다(예: `의거`, `단,`, `갖춘자로`, 부칙 `① (시행일)`). **서식만 따르고 문구 관행은 따르지 않는다** — 문구는 4단계 기준 적용.

### 2-1. 규정 개정 요청서 — 「제 규정 제정ㆍ개정ㆍ폐지 요청서」
양식의 표 항목을 순서대로 모두 채운다. 각 내용 줄은 `•` 글머리로 시작하고, 해당 없으면 `-` 를 적는다.

| 항목 | 작성 방법 |
|------|-----------|
| 규 정 명 | 홑낫표로 감싼 정식 명칭: `「직원보수규정」` |
| 구    분 | `□ 제 정` `■ 개 정` `□ 폐 지` — 해당 칸만 ■ |
| 주무부서 | 규정 소관 부서 (예: 인사총무팀) |
| 관련부서 | 영향 받는 부서, 전 부서 해당 시 `전체 부서` |
| 개정사유 | 왜 바꾸는지 — 상위법령 개정·법령 불일치, 제도 변경, 자구 정비 등을 항목별 `•` 로 |
| 관련근거 | 근거 법령·조문: `• 「근로기준법」 제60조제6항` 형식 |
| 주요내용 | 조문별 개정 요지를 `•` 로, 가능하면 `(안 제〇조제〇항)` 위치 병기 |
| 기대효과 | 개정으로 얻는 효과 (법령 준수, 분쟁 예방 등) |
| 구성원 의견수렴/기타사항 | 의견수렴 결과, 노무자문 여부 등 / 없으면 `-` |
| 첨    부 | `• 「〇〇규정」 신·구조문 대비표 1부` |

### 2-2. 신·구조문 대비표
제목은 `「〇〇규정」 신·구조문 대비표`, 표 머리는 `현      행` | `개  정  안` 2단. 원칙은 법제처 신구조문대비표 방식이다.
- 개정되는 **조 단위**로 행을 만들고 조문 순서대로 배열한다. 개정이 없는 조는 싣지 않는다.
- 조 안에서 변경 없는 항·호: 개정안 칸에 `① (현행과 같음)` 처럼 번호 + `(현행과 같음)`.
- 한 항 안에서 일부만 바뀔 때: 개정안 칸에서 그대로인 앞부분을 `------` 로 줄이고 바뀐 부분만 적는다. (정관 예시 제92조제2항 방식)
- 바뀐 부분 표시: 현행 칸은 바뀌거나 삭제되는 문구, 개정안 칸은 새 문구에 **진하게 + 밑줄**(양식 글자모양 중 굵게·밑줄 스타일 사용). 빨간 글자는 쓰지 않는다.
- 신설: 현행 칸에 `⑤ <신 설>`, 개정안 칸에 신설 문구 전문.
- 삭제: 현행 칸에 기존 문구, 개정안 칸에 `⑤ <삭 제>`.
- 별표·별지 서식 개정: 대비표 아래에 별도 2단 표로 `현행 【별표4】` | `개정안 【별표4】` 전체를 싣는다.
- 부칙: 표 마지막 행에 개정안 칸에만 기재(현행 칸 공란). 부칙 작성 방식은 drafting-standards.md Ⅰ-5.

## 3단계. 엑셀 검토의견·개정안 검증

검토의견 엑셀을 받으면 **모든 행**을 대상으로 아래를 수행하고, 결과를 검증표로 정리한다.

1. 엑셀 구조 파악: 시트별로 조문 번호, 현행, 검토의견, 개정(안), 반영 여부, 비고 등 열을 식별한다. 병합 셀·숨김 행·숨김 시트·메모까지 확인한다.
   - **법령 검토의견 엑셀 표준 열** (예: `regulation/input/검토의견/규정_법령검토의견_20261106.xlsx`):
     `A 규정 | B 조문 | C 관련 법령 | D 법령 조문 | E 판정 | F 요지 | G 근거 | H 개선 제안 | I 검토일자`
   - 한 엑셀에 여러 규정이 섞여 있으면 A열(규정)로 묶어 **규정별로 작업 단위**를 나눈다. 같은 규정·같은 조문에 여러 행이 있으면 함께 반영한다(예: 직원인사규정 제28조 2건).
   - E열 판정 처리 우선순위: `법령 위반·불일치` → `개정 필요` → `확인 필요`.
     `확인 필요` 행은 본문·별표 확인 후에도 개정 여부가 판단되지 않으면 자동으로 `확인필요`로 분류하고 사용자에게 묻는다.
   - G·H열에 인용된 **법령 조문은 현행 법령과 일치하는지 다시 확인**한다(국가법령정보센터 기준, 개정·신설 시기 포함). 검토의견이 틀릴 수 있다는 전제로 검증한다.
   - H열 개선 제안 문구는 그대로 옮기지 않고 4단계 작성 기준에 맞는 조문으로 다시 쓴다.
2. 행마다 규정 본문(1단계 원본)과 대조:
   - **조문 번호 일치**: 엑셀에 적힌 조·항·호·목이 실제 본문 위치와 맞는가
   - **현행 문구 일치**: 엑셀의 "현행"이 원문과 한 글자도 다르지 않은가 (다르면 원문 기준으로 바로잡고 표시)
   - **개정안 적정성**: 검토의견 취지가 개정안에 제대로 반영되었는가, 4단계 입안 기준 위반은 없는가
   - **파급 영향**: 조문 신설·삭제·이동으로 다른 조문의 인용(「제〇조제〇항에 따라」 등), 별표·서식 번호, 용어 정의가 깨지지 않는가 → 규정 전체를 검색해 연쇄 수정 대상 찾기
   - **상위규범 저촉**: 학칙, 관련 법령, 다른 규정과 충돌하지 않는가 (확인 불가 시 "확인 필요"로 표시)
3. 검증 결과 분류
   - `반영` : 그대로 반영
   - `수정반영` : 취지는 반영하되 문구를 기준에 맞게 다듬음 (수정 전/후와 이유 기재)
   - `미반영` : 반영하지 않음 (사유 기재)
   - `확인필요` : 사용자 판단이 필요 — **임의로 결정하지 않고 사용자에게 질문**
4. 검증 결과는 `검증보고.md`(및 요청 시 엑셀 "검증결과" 열 추가본)로 남기고, `확인필요` 항목을 먼저 사용자에게 보고한 뒤 결과물을 확정한다.

## 4단계. 규정문 작성 기준

규정문은 **법제처 「법령 입안·심사 기준」** 과 **청주대학교 내부 기준**에 따라 작성한다.
세부 기준은 [references/drafting-standards.md](references/drafting-standards.md) 를 반드시 읽고 적용한다.
내부 기준과 법령입안심사기준이 충돌하면 **내부 기준을 우선**한다.

## 5단계. 결과물 작성 및 최종 점검

1. 개정안 규정 파일: 원본 파일을 복사한 뒤 개정 조문만 수정한다. 조문 끝 개정 이력 `<개정 YYYY. M. D.>`, 부칙 추가, 목차·조문 제목 갱신을 반영한다. 원본 서식(글꼴, 들여쓰기, 문단 모양)을 유지한다.
2. 신구대비표 → 개정안 파일 → 개정요청서 순서로 내용이 서로 **완전히 일치**하는지 대조한다.
3. 최종 점검 체크리스트 (모두 통과해야 제출)
   - [ ] 3종 결과물이 모두 있고 파일명 규칙을 따랐다
   - [ ] 엑셀 검토의견 전 행이 검증표에 빠짐없이 처리되었다
   - [ ] 신구대비표의 현행 문구가 원문과 정확히 일치한다
   - [ ] 신구대비표 개정안 = 개정안 파일 본문
   - [ ] 개정요청서의 주요 개정내용이 신구대비표와 일치한다
   - [ ] 조문 인용·번호 체계·별표/서식 번호가 깨지지 않았다
   - [ ] 부칙(시행일, 필요 시 경과조치)이 있다
   - [ ] 날짜·숫자·띄어쓰기·용어가 작성 기준을 따른다
4. 사용자에게 보고: 결과물 경로, 주요 개정 내용 요약, `수정반영`/`미반영`/`확인필요` 항목과 사유.

## 양식·기준 관리

- 업로드받은 양식은 `regulation/templates/` 에 보관한다 (현재 등록 상태는 `regulation/templates/README.md` 참고).
- 양식이 아직 없으면 작업 전에 사용자에게 업로드를 요청한다. 양식 없이 임의 양식으로 만들지 않는다.
- 사용자가 새 기준·선호를 알려주면 이 지침(또는 drafting-standards.md의 "내부 기준")에 추가해 다음 개정부터 동일하게 적용한다.
